Eventia - Aprobar Plantillas SuperAdmin

Caso: los usuarios que no encontraron plantillas para aplicar a su evento crearon sus propios tramos, accesos y relaciones y dejaron pendientes solicitudes de plantillas que el SuperAdmin deberá aprobar o rechazar

El SuperAdmin tendrá:
Bandeja de solicitudes 
Vista detalle 
Acciones (aprobar/rechazar/convertir)


Menú (sidebar): Plantillas

Solicitudes de Plantillas
	Objetivo: que el SuperAdmin vea qué usuarios no encontraron plantillas (o ninguna le sirvió) y pueda:
revisar
aprobar y convertir en plantilla
rechazar con motivo

Columnas de la Bandeja:
ID Solicitud (id_solicitud)
Fecha (fecha_alta)
Estado (D / P / A / R)
Tipo de evento (id_tipo_evento + texto traducido según idioma admin)
Evento (id_evento + botón “Ver estructura del evento”? ver si suma algo)
Usuario (id_usuario_solicita)
Motivo 
Detalle (preview 1 línea)
Acciones: Ver | Convertir | Rechazar
Filtros (arriba)
Estado: Pendientes (default) / Draft / Aprobadas / Rechazadas / Todas
Tipo evento (combo)
Fecha desde / hasta (opcional)
Defaults 
Entrar con estado P (pendientes)
Orden: más nuevas primero

Endpoints
Pendientes por tipo de evento:
GET /solicitudes_plantilla/pendientes?idTipoEvento=4 (opcional)
Pendientes cualquier tipo de evento:
GET /solicitudes_plantilla/pendientes

Mostrar 3 tabs:
Tab 1: Tramos
Tabla:

nombre
leyenda_visible
Tab 2: Accesos
Tabla:
orden
nombre
mensaje_rsvp

Tab 3: Relaciones
Matriz de relaciones - checks (la misma del wizard):
filas: accesos
columnas: tramos
checks según payload

Acciones del Superadmin (workflow final)
A) Rechazar
Botón: Rechazar
Campo obligatorio: observaciones_admin (“por qué no sirve / qué corregir”)
Cambia: estado ? R

Endpoint:
PUT /solicitudes_plantilla/{idSolicitud}/revisar

{
  "estado": "R",
  "observaciones_admin": "No es reutilizable como plantilla general porque falta xxxxxx"
}

Resultado:
estado = R
fecha_revision set
id_usuario_revisa set


B) Aprobar y convertir en plantilla
Botón: Convertir en plantilla
Abre modal/pantalla con:
codigo (obligatorio, único). Ejemplo: CUMPLE15_RECEPCION_CENA_FIESTA
activo (default true)
observaciones_admin (opcional)

Endpoint:
POST /solicitudes_plantilla/{idSolicitud}/convertir

{
  "codigo": "CUMPLE15_RECEPCION_CENA_FIESTA",
  "observaciones_admin": "Aprobada. Buena estructura estándar para 15.",
  "activo": true
}
Resultado:
Crea:
ef_plantillas_evento
ef_plantilla_tramos
ef_plantilla_accesos
ef_plantilla_acceso_tramos
Actualiza solicitud:
estado = A
fecha_revision
id_usuario_revisa
observaciones_admin
{
    "ok": true,
    "id_plantilla": 4
}
